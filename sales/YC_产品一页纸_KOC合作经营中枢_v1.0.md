# YC KOC合作经营中枢｜产品一页纸

## 一句话

**不替换飞书、抖音、云仓和员工现有习惯，把KOC合作中的寄样、合作单、内容、数据和成本连接成可执行、可跟进、可核算的业务闭环。**

## 企业当前问题

- KOC信息反复登记在多个系统；
- 云仓发货、物流、抖音合作单需要持续查询和回填；
- 状态更新不及时，异常依赖员工记忆；
- 管理者看不到整体漏斗、超时和责任；
- 财务难以核算每个KOC的真实成本和收益；
- 单独脚本难以交付、维护和复制。

## YC第一版怎么解决

### KOC合作业务壳

统一展示：达人、产品、商务条件、寄样、合作单、内容、数据、成本、责任人、下一步和异常。

### Cell A：云仓寄样履约

飞书读取 → 数据校验 → 创建发货单 → 查询发货/物流 → 飞书回写 → 证据与异常。

### Cell B：抖音合作单

合作码/KOC ID读取 → 重复检查 → 创建合作单 → 回写ID → 跟进达人确认 → 超时异常。

## 员工怎么用

- 继续使用飞书和微信；
- 维护少量标准字段；
- 处理审批、异常和需要人工判断的事情；
- 不再反复查询、复制和做非标日报。

## 管理者能看到

- KOC合作整体漏斗；
- 每个案例卡在哪一步；
- 自动完成率和人工介入率；
- 超时、异常和责任人；
- 节省工时；
- 基础成本和数据完整度；
- 跨平台执行时间线与证据。

## 部署方式

```text
YC Cloud（阿里云）：业务状态、审批、异常、看板
        ↓ 安全出站连接
企业内部YC Edge：账号、登录态、受限执行
        ↓ 本机调用
Browser Service：控制已登录浏览器
```

平台登录态留在企业本地；云端不能任意控制浏览器。

## 30天试点

- 1家企业；
- 1个KOC团队；
- 1套飞书台账；
- 1个云仓账号；
- 1个抖音账号；
- 2个深自动化Cell；
- 每周复盘；
- 输出效果和扩展建议。

## 预期验证指标

- 员工节省工时；
- 自动处理成功率；
- 台账回写及时率；
- 重复/漏处理事故；
- 异常处理时长；
- 创始人/YC维护时间；
- 试点后是否值得扩展。

## 合作方式

AI业务诊断 → 30天付费试点 → 托管运行 → 扩展相邻业务单元。
